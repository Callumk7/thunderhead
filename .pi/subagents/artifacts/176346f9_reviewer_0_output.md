## Review
- **Blocker — `src/agents/issue-strengthener.ts:28-33,69-75`:** The finish reminder appends a signal without `teamId` or `deliveryId`. Flue advances `useDelivery()` to appended application signals, so the continuation re-renders against this reminder and immediately throws “missing trusted team or delivery ID.” This breaks enforcement whenever the model stops without a terminal action. **Smallest safe fix:** copy both trusted attributes onto the appended signal.
- **Blocker — `src/agents/issue-strengthener.ts:47-53`, `src/tools/linear-issue.ts:43-145`:** `publish_strengthened_issue` is always mounted and performs no repository-access validation. It remains callable when no repository is mapped, before any repository read, or after a GitHub tool fails. Thus prompt noncompliance can cause the prohibited repository-free rewrite. **Smallest safe fix:** do not mount publish without a mapping; track successful/failed repository access per delivery and only expose/allow publish after a successful read with no failure.
- **High — `src/channels/linear.ts:27-34`, `src/agents/issue-strengthener.ts:56-67`:** Every trigger for an issue shares one agent instance, while `useAgentFinish` counts terminal tool calls across the entire response. Flue responses may absorb multiple joined deliveries, so a successful publication from delivery A can make delivery B appear complete without any B-specific terminal action. **Smallest safe fix:** scope terminal accounting to `deliveryId`, using delivery-specific durable completion state or delivery-specific terminal tool identity rather than response-wide name counts.
- **Medium — `src/shared/linear-client.ts:56-65`:** The SDK methods return paginated `Connection` objects, but only the first 250 team labels and last 250 comments are read. This contradicts `get_linear_issue`’s “every existing label” contract and can miss an older delivery marker, permitting duplicate comments. **Smallest safe fix:** exhaust label pages with `fetchNext()` and comment pages with `fetchPrevious()` before consuming `nodes`.
- **Low — `src/shared/linear-trigger.test.ts`, `src/tools/linear-issue.test.ts`:** Tests exercise pure filtering and standalone tool handlers but not an actual agent continuation, joined delivery, or repository-gated publication. Consequently, the lifecycle and cross-delivery failures above are uncovered. **Smallest safe fix:** add Flue harness tests for reminder continuation, two joined deliveries, no mapping, and failed repository reads.
